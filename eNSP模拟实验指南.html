eNSP模拟实验指南 — 照明项目网络通信仿真

本指南基于华为eNSP仿真平台，完整重现照明项目的网络通信拓扑—— 从核心交换机VLAN划分、DHCP分配、路由器NAT出口，到终端设备（网关/服务器/摄像头）的跨VLAN通信验证。 跟着做一遍，项目的网络原理就全通了。

前置条件
• 已安装eNSP（推荐eNSP V100R003C00或更高版本）
• 已安装VirtualBox（eNSP依赖VirtualBox运行PC和路由器镜像）
• 已安装Wireshark（eNSP内置抓包需要）
• 如遇路由器/交换机启动失败，检查eNSP → 工具 → 设置 → VirtualBox路径是否正确

实验要点速览
  • 复现的真实拓扑：4 个 VLAN（照明/服务器/安防/管理）+ 出口路由器 AR2220 + 二层交换机 S5700（核心）/ S3700（接入）+ 云平台模拟。
  • 三层互联：S5700 配 VLANIF 作网关，S3700 做二层透传；交换机能配 DHCP，终端自动获取 IP。
  • 出口与路由：AR2220 做 NAT 出口、指默认路由/静态路由，内网才能访问"公网云平台"。
  • 验证闭环：同 VLAN、跨 VLAN（ping 网关/异地 VLANIF）、NAT 出网三层连通性逐一验证；用 Wireshark 抓 DHCP/ARP/ICMP 报文核对协议行为。
  • 可还原：实验完毕保存 .bat/.topo 拓扑 + 配置文件，供复查与复现项目组网。

1 实验目标与拓扑设计

1.1 实验目标

  • 重现项目网络拓扑：4个VLAN（照明/服务器/安防/管理）+ 路由器出口 + 云平台
  • 验证DHCP分配：交换机做DHCP服务器，终端自动获取IP
  • 验证跨VLAN通信：不同VLAN的设备能互相ping通
  • 验证NAT出口：内网设备能访问"公网"（模拟云平台）
  • 抓包验证协议：用Wireshark抓取DHCP/ARP/ICMP报文

4 核心交换机配置（S5700）

双击Core-Switch打开CLI，按以下顺序配置。这是整个实验的核心。

4.1 VLAN创建

system-view
sysname Core-Switch

# 批量创建VLAN
vlan batch 10 20 30

# 验证
display vlan

4.2 VLANIF接口配置（各VLAN网关）

# VLAN1 管理网关
interface Vlanif 1
 ip address 192.168.1.1 255.255.255.0
 quit

# VLAN10 照明网关
interface Vlanif 10
 ip address 192.168.10.1 255.255.255.0

# VLAN20 服务器网关

# VLAN30 安防网关
interface Vlanif 30
 ip address 192.168.30.1 255.255.255.0

# 验证所有VLANIF
display interface Vlanif brief

4.3 端口划分VLAN

# GE0/0/1 → 下联Access-SW-1F（Trunk模式）
interface GigabitEthernet0/0/1

# GE0/0/2 → 下联Access-SW-2F（Trunk模式）
interface GigabitEthernet0/0/2
 port link-type trunk
 port trunk allow-pass vlan 1 10 20 30

# GE0/0/10 → Edge-Server（Access VLAN20）

# GE0/0/20 → NVR（Access VLAN30）
interface GigabitEthernet0/0/20

# GE0/0/23 → Debug-PC（Access VLAN1）

4.4 DHCP服务器配置

# 全局开启DHCP
dhcp enable

# VLAN1 地址池（管理）

 dns-list 8.8.8.8 114.114.114.114

 excluded-ip-address 192.168.1.254

# VLAN10 地址池（照明）
ip pool VLAN10-POOL
 network 192.168.10.0 mask 255.255.255.0
 gateway-list 192.168.10.1
 dns-list 8.8.8.8 114.114.114.114

 excluded-ip-address 192.168.10.2 192.168.10.99
 excluded-ip-address 192.168.10.201 192.168.10.254

# VLAN20 地址池（服务器段，预留少量DHCP）

 dns-list 8.8.8.8 114.114.114.114

# VLAN30 地址池（安防）

 dns-list 8.8.8.8 114.114.114.114
 lease day 1 hour 0 minute 0

 excluded-ip-address 192.168.30.2 192.168.30.49

# 在VLANIF接口上应用DHCP

interface Vlanif 10

interface Vlanif 20

interface Vlanif 30

# 验证DHCP

6 出口路由器配置（AR2220）

路由器负责NAT转换——把内网私有IP转成公网IP，模拟项目现场的防火墙/出口网关。

6.1 接口IP配置

system-view
sysname Router-Edge

# GE0/0/0 → 内网侧（接核心交换机）
interface GigabitEthernet0/0/0
 ip address 192.168.1.254 255.255.255.0
 description To-Core-Switch
 quit

# GE0/0/2 → 公网侧（接Cloud）
interface GigabitEthernet0/0/2
 ip address 202.1.1.2 255.255.255.252
 description To-Internet
 quit

# 验证接口
display ip interface brief

6.2 默认路由（指向Cloud/公网）

# 默认路由指向Cloud侧的网关（202.1.1.1）
ip route-static 0.0.0.0 0.0.0.0 202.1.1.1

# 验证路由表
display ip routing-table

6.3 NAT配置（Easy IP方式）

# 1. 定义ACL匹配内网网段
acl number 2000
 rule permit source 192.168.0.0 0.0.255.255
 quit

# 2. 在公网口上配置NAT（Easy IP = 用接口IP做转换）
interface GigabitEthernet0/0/2
 nat outbound 2000
 quit

# 3. 验证NAT
display nat outbound
display nat session all

6.4 DHCP中继（可选）

# 本实验DHCP服务器在核心交换机上，终端直连核心交换机的端口
# 不需要DHCP中继。如果终端在接入交换机后面，Trunk链路会透传DHCP广播
# 所以这里不需要额外配置DHCP中继

8 云平台模拟（Internet）

eNSP的Cloud设备用于桥接本机网络，模拟公网出口。

8.1 Cloud配置

  1. 双击Cloud设备，打开"Cloud配置"窗口
  2. 在"绑定信息"区域，选择"UDP" → 点击"增加"
    • 绑定信息：UDP
    • 本地端口：1000（随意，不冲突即可）
    • 对端端口：1001
    • 对端IP：127.0.0.1
  3. 再选"GE" → 选一个本机网卡 → 点击"增加"
    • 这样Cloud的GE口桥接到本机的物理网卡
    • 如果你的电脑能上网，内网PC就能通过NAT访问真公网
  4. 或者，只添加UDP绑定，不桥接本机网卡—— 这样Cloud只是一个"黑洞"接口，模拟公网连通性即可， 不需要真正联网
  5. 关闭Cloud配置窗口
Cloud配置注意
• 如果eNSP弹出VirtualBox错误，说明Cloud的GE桥接需要VirtualBox支持
• 如果只是模拟内网通信，不验证NAT出口，可以不用Cloud设备
• Cloud的IP地址需要在路由器上手动配（见第6章，公网侧IP 202.1.1.1/30）
• eNSP的Cloud不像路由器能配IP，它只是一个二层桥接设备

8.2 替代方案：用路由器模拟公网

如果Cloud不好用，可以用另一台路由器模拟公网侧：

# 在拓扑中再加一台AR2220，命名为 ISP-Router
# ISP-Router 配置：

10 抓包分析与协议验证

eNSP内置Wireshark，可以在任何链路上抓包，验证协议交互过程。

10.1 抓取DHCP分配过程

  1. 在eNSP拓扑中，找到PC1到Access-SW-1F的连线
  2. 右键连线 → "抓包" → 自动打开Wireshark
  3. 在PC1命令行执行：ipconfig /release 然后立刻 ipconfig /renew
  4. 回到Wireshark，观察抓到的DHCP报文
# DHCP完整交互过程（4个报文）：
# 1. DHCP Discover  (PC → 0.0.0.0 → 255.255.255.255)
#    PC广播"我需要IP"，源IP=0.0.0.0，目的IP=广播

# 2. DHCP Offer     (交换机 → 255.255.255.255)
#    交换机回复"给你192.168.10.110"

# 3. DHCP Request   (PC → 255.255.255.255)
#    PC广播"我要192.168.10.110这个IP"

# 4. DHCP Ack       (交换机 → 255.255.255.255)
#    交换机确认"分配给你了，租约7天"

# 在Wireshark过滤栏输入 bootp 或 dhcp 过滤
# 可以清楚看到4个报文的交互时序

10.2 抓取ARP解析过程

# 在PC1到交换机连线上抓包
# PC1 ping PC5 时先发ARP请求：

# 1. ARP Request  (PC1 → 广播)
#    "谁是192.168.10.1？请告诉我"（PC1先要找自己的网关MAC）

# 2. ARP Reply    (交换机VLANIF10 → PC1)
#    "192.168.10.1的MAC是xx-xx-xx-xx"

# 在Wireshark过滤栏输入 arp 过滤
# ARP是二层协议，只在同VLAN内广播，跨VLAN时网关代答

10.3 抓取ICMP跨VLAN过程

# PC1 ping PC5 (跨VLAN10→VLAN20)
# 在Core-Switch的GE0/0/1口抓包，可以看到：

# 1. PC1 → 交换机：ICMP Echo Request
#    源MAC=PC1_MAC, 目的MAC=VLANIF10_MAC（网关）
#    源IP=192.168.10.110, 目的IP=192.168.20.100

# 2. 交换机 → PC5：ICMP Echo Request（已改MAC）
#    源MAC=VLANIF20_MAC, 目的MAC=PC5_MAC
#    源IP=192.168.10.110, 目的IP=192.168.20.100 (IP不变)

# 3. PC5 → 交换机：ICMP Echo Reply
# 4. 交换机 → PC1：ICMP Echo Reply（已改MAC）

# 关键理解：跨VLAN时，IP地址不变，MAC地址在每跳都变
# 这就是三层路由的本质

10.4 抓取NAT转换过程

# 在Router-Edge的GE0/0/2（公网口）抓包
# PC1 ping 139.224.67.85 时：

# 出方向（PC1 → 公网）：
# 源IP从 192.168.10.110 → 被NAT改成 202.1.1.2
# 目的IP不变 139.224.67.85

# 回方向（公网 → PC1）：
# 目的IP从 202.1.1.2 → 被NAT改回 192.168.10.110

# 在Wireshark中可以看到NAT转换前后的IP对比

  eNSP实验小结
  
完成本实验后，你应该理解了以下项目网络原理：
  
• VLAN隔离：不同VLAN的二层广播域是隔离的，跨VLAN通信必须经过三层设备（VLANIF）
  
• DHCP分配：交换机做DHCP服务器，终端通过Discover→Offer→Request→Ack四步获取IP
  
• 静态绑定：IP+MAC绑定确保网关设备每次拿到固定IP
  
• Trunk链路：核心和接入交换机之间用Trunk放行多个VLAN
  
• NAT出口：内网私有IP通过NAT转换为公网IP访问云平台
  
• 跨VLAN路由：三层交换机VLANIF接口做网关，实现VLAN间路由
  

  
这些原理在现场调试时就是排查问题的底层逻辑——
  ping不通先看VLAN对不对、DHCP分配对不对、网关指没指对。





  从eNSP到现场的区别
  
• eNSP中PC代表实际项目中的网关/服务器/摄像头等设备
  
• 现场设备的IP配置在各自的Web后台，不是在命令行
  
• 现场的DALI总线、蓝牙Mesh等不在eNSP模拟范围内（eNSP只模拟以太网层）
  
• 现场可能有PoE供电问题、网线质量问题等物理层故障，eNSP中没有
  
• eNSP用于理解网络原理和验证配置命令，现场实施还需结合设备实际情况
